1. Why this lab exists

Some jobs do not have one checklist. A credit analyst (the person who recommends whether the bank should lend) has to decide the steps from the file in front of them. A factory and a company that sells software by subscription do not share one fixed list.

The planner writes the steps. The executor does one step, then either takes the next step, goes back because the step cannot be done, or finishes. The new steps have to follow what the executor just found. A fixed checklist would keep asking for a number the file cannot give.

What you will build

  1. A planner that writes an ordered list of steps, and later rewrites only the steps that are not done yet.
  2. An executor that does the current step against the file and returns continue, blocked, or done.
  3. A Python router that turns that status into the next node. The model does not choose the arrow. It only judges the step.

2. The business story

The file on the analyst’s desk

A private manufacturer (a factory company that is not listed on a stock exchange) wants working capital: money for day-to-day stock and bills, not for buying a new factory. The file has a short brief, two years of GST returns, and bank statements. There are no audited financials.

  • planner reads the file and writes the steps in order: rebuild sales from the GST returns, check that money coming into the bank matches those sales, see whether a few buyers make up most of the sales, then write the recommendation and list what is still missing.
  • executor does one step. It writes what it found, then moves to the next step.
  • One step gets stuck: “To see if a few buyers make up most of the sales, I need buyer names. The bank statement only shows account numbers.” The executor stops and sends the case back to planner.
  • The planner drops that stuck step and rewrites what is left: say that customer concentration is unknown, and do not invent buyer names. The executor continues with the new remaining steps and writes the memo.

Words you need

Credit memo
A short note that says yes or no to the loan, and why. It must also say what the file does not contain.
GST returns
The tax filings that list sales. Here they are the only sales numbers in the file.
Audited financials
Accounts checked and signed by an outside auditor. This file does not have them.
Customer concentration
How much of the sales sits with a few buyers. You cannot measure it without buyer names.
Cursor
The position of the step being done now. Step 0 is the first step.
Replan
The executor was blocked. The planner replaces the steps from the cursor onward. Finished steps stay.

3. Why an agent has to do this

  • The right steps depend on the business. One hardcoded list would be wrong for the next file.
  • Noticing that an account number is not a buyer name is a judgment about the evidence. The executor has to say the step cannot be done.
  • The new steps have to follow that finding. A fixed checklist would keep asking for a percentage the file cannot give.

The router itself is ordinary Python. It does not “decide” in the way the handoff lab does. It turns blocked / continue / done into replan / next_step / done. The judgment stays inside the two model calls.

The planner always hands to the executor (solid arrow). The executor’s dotted arrows choose the next step, a new plan, or the end.

  • planner writes the list of steps and sets cursor to 0. A solid arrow then goes to executor.
  • The executor reads steps[cursor], does it, and appends a finding.
  • next_step comes back to the same node. One executor node is enough, because the step text lives in state.
  • replan goes back to planner. The planner replaces only the steps that are not done yet.
  • done fires when the executor says the memo is written, when the cursor is past the last step, or when the replan limit is used up.

Which step number will come back blocked? What should the planner delete, and what two steps should replace it? You will check this against the printed plan and the replan.

7. State

findings uses operator.add, so each step appends a line and earlier lines stay. steps, cursor, status, replan_count, and memo are replaced, not appended. If you put operator.add on steps, a replan would glue the new list onto the old one.

class State(TypedDict):

    steps: list
    cursor: int
    findings: Annotated[list, operator.add]
    status: str
    replan_count: int

8. What the two models must return

Your Task

New cell.

class Plan(BaseModel):
    steps: list[str] = Field(description="Ordered steps. One short sentence each. 4 steps on the first plan.")
    why: str = Field(description="One sentence on why this order fits this file.")

class RemainingPlan(BaseModel):
    remaining_steps: list[str] = Field(
        description="Only the steps still to do. Do not repeat finished steps. Drop any step the file cannot support."
    )
    why: str = Field(description="One sentence: which step you dropped, and what replaced it.")

class StepResult(BaseModel):
    finding: str = Field(description="What this step found, using only numbers and names that are in the file.")
    status: Literal["continue", "blocked", "done"] = Field(
        description="blocked = this step cannot be done from the file. continue = step done, more remain. done = this finding is the credit memo."
    )

print("Schemas ready.")

9. Planner prompts

The first plan is constrained so the whole class hits the same stuck step. The lesson is the replan, not whether the model invents a clever checklist. The replan prompt is the real planner behavior: keep what is done, drop what is impossible, do not invent buyer names.

Your Task

New cell.

FIRST_PLAN_PROMPT = """You are a credit planner at Horizon Bank. You do not write the memo. You only list steps.

The file is a private manufacturer asking for working capital. Write exactly these four steps, in this order, in your own words:
1. Rebuild annual sales from the two GST years in the file.
2. Check whether bank credits support those sales.
3. Measure customer concentration: what share of sales sits with the named top buyers. This step needs buyer names.
4. Write the credit memo: a yes or no with conditions, and list what is still missing, including audited financials.

Do not add a step that needs stock, collateral, or a factory visit. Those documents are not in the file.
"""

REPLAN_PROMPT = """You are a credit planner. The executor is blocked. Finished steps must stay finished.
You are given the finished findings and the stuck step.

Rewrite ONLY the remaining work:
- Drop the stuck step. Do not ask again for a percentage the file cannot give.
- First remaining step: state that customer concentration is unknown because the file has account numbers, not buyer names. Do not invent buyer names.
- Second remaining step: write the credit memo. Recommend or decline working capital with conditions, and list the gaps still open (no audited financials, concentration unknown).

Return two remaining steps, not the full history.
"""

EXECUTOR_PROMPT = """You are the credit executor. Do the ONE current step. Use only the credit file and the findings so far.

Status rules:
- If the step asks for buyer names, customer names, or a concentration percentage, and the file has only masked account numbers, status=blocked. Say what is missing. Do not invent a name or a percentage. Do not write the memo in this finding.
- If the step tells you to record that concentration is unknown and not to invent names, write that finding and status=continue.
- If the step is to write the credit memo, status=done, and the finding IS the memo: 2 short paragraphs, a clear yes or no with conditions, GST sales, whether bank credits support them, concentration unknown, no audited financials.
- Otherwise do the step with the numbers in the file and status=continue.

Never treat an account number like XX4412 as a buyer name.
"""

first_plan_chain = ChatPromptTemplate.from_messages([
    ("system", FIRST_PLAN_PROMPT),
    ("human", "Credit file:\n{file_text}"),
]) | llm.with_structured_output(Plan)

replan_chain = ChatPromptTemplate.from_messages([
    ("system", REPLAN_PROMPT),
    ("human", "Stuck step:\n{stuck}\n\nFindings so far:\n{findings}\n\nCredit file:\n{file_text}"),
]) | llm.with_structured_output(RemainingPlan)

executor_chain = ChatPromptTemplate.from_messages([
    ("system", EXECUTOR_PROMPT),
    ("human", "Current step:\n{step}\n\nFindings so far:\n{findings}\n\nCredit file:\n{file_text}"),
]) | llm.with_structured_output(StepResult)

print("Chains ready.")

10. The planner node

On the first visit, steps is empty, so the planner writes the full list and sets cursor to 0. On a later visit, it keeps steps[:cursor] and replaces everything from the cursor onward. replan_count goes up by one.

Your Task

New cell.

def planner(state):
    if not state["steps"]:
        plan = first_plan_chain.invoke({"file_text": state["file_text"]})
        print("\n[planner] first plan")
        for i, step in enumerate(plan.steps, start=1):
            print(f"  {i}. {step}")
        print("   why:", plan.why)
        return {
            "steps": plan.steps,
            "cursor": 0,
            "status": "continue",
            "replan_count": 0,
            "memo": "",
        }

    stuck = state["steps"][state["cursor"]]
    plan = replan_chain.invoke({
        "stuck": stuck,
        "findings": "\n".join(state["findings"]),
        "file_text": state["file_text"],
    })
    kept = state["steps"][: state["cursor"]]
    new_steps = kept + plan.remaining_steps
    print("\n[planner] replan")
    print("   dropped:", stuck)
    print("   why:", plan.why)
    for i, step in enumerate(new_steps, start=1):
        mark = "done" if i - 1 < state["cursor"] else "left"
        print(f"  {i}. [{mark}] {step}")
    return {
        "steps": new_steps,
        "status": "continue",
        "replan_count": state["replan_count"] + 1,
    }

print("Planner node ready.")

11. The executor node

The executor does not increment the cursor when the step is blocked. The stuck step stays at cursor, so the planner can replace it. On continue or done, the cursor moves forward by one.

Your Task

New cell.

def executor(state):
    step = state["steps"][state["cursor"]]
    print(f"\n[executor] step {state['cursor'] + 1} of {len(state['steps'])}")
    print("   ", step)
    result = executor_chain.invoke({
        "step": step,
        "findings": "\n".join(state["findings"]) or "(none yet)",
        "file_text": state["file_text"],
    })
    print(f"   status={result.status}")
    print(f"   {result.finding}")
    update = {
        "findings": [f"Step {state['cursor'] + 1} ({result.status}): {result.finding}"],
        "status": result.status,
    }
    if result.status != "blocked":
        update["cursor"] = state["cursor"] + 1
    if result.status == "done":
        update["memo"] = result.finding
    return update

print("Executor node ready.")

12. The router is Python

This function is the dotted arrows. It does not call the model.

  • blocked and fewer than 2 replans: go back to the planner.
  • done, or the cursor is past the last step: end.
  • blocked after the replan limit: end anyway. Otherwise a step that stays impossible would spin until recursion_limit.
  • Anything else: the same executor node, next step.
A first sketch of this router often forgets the third case. If the cursor does not move on blocked, and replans are used up, cursor >= len(steps) is still false. The router would send the executor back to the same stuck step forever. The explicit stop is part of the lab.
Your Task

New cell. Then answer, on paper: if status is blocked and replan_count is already 2, which string does this return?

def after_executor(state):
    if state["status"] == "blocked" and state["replan_count"] < 2:
        return "replan"
    if state["status"] == "done" or state["cursor"] >= len(state["steps"]):
        return "done"
    if state["status"] == "blocked":
        return "done"
    return "next_step"

print("Router ready.")

13. Wire the graph

The only solid edge between the two workers is planner to executor. The executor’s three exits are conditional. next_step points at executor itself.

Your Task

New cell.

from langgraph.graph import StateGraph, START, END

g = StateGraph(State)
g.add_node("planner", planner)
g.add_node("executor", executor)
g.add_edge(START, "planner")
g.add_edge("planner", "executor")
g.add_conditional_edges("executor", after_executor, {
    "next_step": "executor",
    "replan": "planner",
    "done": END,
})
graph = g.compile()
print("Graph compiled.")

def run_memo():
    result = graph.invoke(
        {
            "file_text": CREDIT_FILE,
            "steps": [],
            "cursor": 0,
            "findings": [],
            "status": "",
            "replan_count": 0,
            "memo": "",
        },
        config={"recursion_limit": 20},
    )
    print("\n" + "=" * 70)
    print("REPLANS:", result["replan_count"])
    print("STEPS LEFT IN STATE:")
    for i, step in enumerate(result["steps"], start=1):
        print(f"  {i}. {step}")
    print("\nFINDINGS:")
    for line in result["findings"]:
        print("-", line)
    print("\nMEMO:\n")
    print(result["memo"] or "(no memo — the run stopped on the replan limit)")
    return result

result = run_memo()

replan_count should be 1. The memo should mention the GST figures, that bank credits are in the same range, that concentration is unknown, and that audited financials are missing. It must not name a buyer.

If the run looks wrong

  • No blocked line. The executor invented a concentration percentage or treated XX4412 as a buyer. The finding is then unsupported. Tighten the executor prompt and run again.
  • The replan repeats the concentration step. The remaining-plan prompt was ignored. The second time that step runs it should still be blocked, and a third replan is refused because replan_count is no longer below 2.
  • The memo appears before the block. The executor wrote the memo on an early step. Only the step that says “write the credit memo” may return done.
  • GraphRecursionError. The router is sending blocked back to the executor. Check that the “replans used up” branch returns done.

16. Key takeaways

  • The plan is data, not a drawing. The same executor node can run every step because the current step is steps[cursor].
  • The model judges the step. Python judges the arrow. blocked is a model status. replan is a router return value.
  • A replan edits the tail of the list. Finished findings stay. The stuck step does not stay in the list.
  • Do not advance the cursor on a blocked step. If you do, the planner will think that step is finished.
  • Cap the replans. After the cap, force an ending that lists the gaps. A file that can never answer must still produce a memo.
