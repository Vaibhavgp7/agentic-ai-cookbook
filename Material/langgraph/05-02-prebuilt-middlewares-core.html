2. Tool Retry Middleware

2.1 What It Does

ToolRetryMiddleware wraps tool execution and automatically retries when a tool raises an exception. It supports exponential backoff, jitter, per-tool filtering, and custom failure handling — ideal for transient network failures on external APIs.

2.2 Use Case: Resilient Financial Research Agent

A financial analyst agent needs live stock quotes from an external market-data API. That API occasionally returns connection errors during peak hours. Without retry middleware, a single timeout kills the agent run; with it, the agent transparently retries and completes the user's request.

Relevant tools:

  • fetch_stock_quote — simulates a flaky REST API (fails twice, then succeeds).
  • tavily_tool — web search for company news (does not need retry).
Your Task

Define the flaky stock-quote tool, attach ToolRetryMiddleware only to that tool, and create the agent. 

from langchain.agents.middleware import ToolRetryMiddleware

# Demo counter — first two calls fail to simulate transient API failures
_quote_attempts = 0

@tool
def fetch_stock_quote(symbol: str) -> str:
    """Fetch the latest stock price for a ticker symbol (e.g. AAPL, MSFT).

    Use this when the user asks for current or live stock prices.
    """
    global _quote_attempts
    ticker = symbol.upper().strip()
    _quote_attempts += 1
    attempt = _quote_attempts

    # Demo: first two calls fail with a transient network error
    if attempt <= 2:
        raise ConnectionError(
            f"Market data API unreachable for {ticker} (attempt {attempt}/3). "
            "This is a simulated transient failure."
        )

    return (
        f"{ticker}: $187.42 (+1.3%) — last updated at market close. "
        f"Succeeded on attempt {attempt}."
    )

retry_agent = create_agent(
    model=model,
    tools=[fetch_stock_quote, tavily_tool],
    middleware=[
        ToolRetryMiddleware(
            max_retries=3,
            initial_delay=0.5,
            backoff_factor=2.0,
            jitter=True,
            tools=["fetch_stock_quote"],          # Only retry the flaky API tool
            retry_on=(ConnectionError, TimeoutError),
            on_failure="return_message",          # Let the model explain failure if all retries fail
        ),
    ],
    system_prompt=(
        "You are a financial research assistant. "
        "Use fetch_stock_quote for live stock prices and Tavily search for recent company news. "
        "If a tool reports repeated failures, explain the situation clearly."
    ),
)

print("Tool-retry agent ready.")
Your Task

Invoke the agent with a request that needs both a stock quote and news. Watch the console — the middleware retries the failing API call before succeeding. 

print("=== Tool Retry Demo: Flaky Stock API ===")

result = retry_agent.invoke({
    "messages": [{
        "role": "user",
        "content": (
            "What is Apple's current stock price, and summarize one recent headline about Apple?"
        ),
    }]
})

print("\nFinal response:")
print(result["messages"][-1].content)
Key configuration options
  • max_retries — retry attempts after the initial call (default: 2).
  • tools — restrict retries to specific tools; omit to retry all tools.
  • retry_on — exception types or a callable filter.
  • on_failure — "return_message", "raise", or a custom formatter.

3.1 What It Does

ShellToolMiddleware exposes a persistent shell session to the agent. Commands run sequentially in the same environment (variables and working directory persist), which is ideal for development automation, testing, and DevOps workflows.

Security Shell middleware executes real commands on the host (by default via HostExecutionPolicy). Use only in trusted environments. For production, consider DockerExecutionPolicy or CodexSandboxExecutionPolicy for isolation.

3.3 Use Case: Release Readiness with uv

A team lead asks: "Is invoice-utils ready to ship?" The agent should sync dependencies, run tests, build the package, and run the deploy script — the same steps a human engineer would run locally before a release.

Typical shell commands the agent discovers:

  • uv --version — confirm uv is available.
  • uv sync --extra dev — install the package and dev dependencies (pytest).
  • uv run pytest -v — run the test suite.
  • uv build — produce wheel/sdist artifacts in dist/.
  • bash scripts/deploy.sh — simulated staging deploy on Linux/macOS (fails if dist/ is missing).
  • powershell -File scripts/deploy.ps1 — same deploy script on Windows.
Shell middleware on Windows

ShellToolMiddleware defaults to /bin/bash, which does not exist on Windows. Install Git Bash first (Section 3.4). This lab points the middleware at C:\Program Files\Git\bin\bash.exe.

Your Task

After Git Bash is installed, copy the helper cell below into your notebook and run it. It puts uv on the shell PATH. 

import os

def _shell_environment() -> dict[str, str]:
    env = dict(os.environ)
    local_bin = Path.home() / ".local" / "bin"
    env["PATH"] = str(local_bin) + os.pathsep + env.get("PATH", "")
    return env
Your Task

Copy the invoice-utils folder into your working directory, then point the shell middleware at it and create an agent with no extra tools — only the auto-injected shell tool.

    f"'{PROJECT_DIR}' not found in the current working directory. "
    "Place the invoice-utils folder next to your notebook and try again."

    model=model,
    tools=[],  # shell only — no custom tools
    middleware=[
        ShellToolMiddleware(
            workspace_root=str(project_root),
            execution_policy=HostExecutionPolicy(),
            shell_command=r"C:\Program Files\Git\bin\bash.exe",
            env=_shell_environment(),
            startup_commands=[
                "uv --version",
                "ls -la",
            ],
        ),
    ],
    system_prompt=(
        "You are a release engineer with shell access to a Python project that uses uv. "
        "The project root is your working directory. "
        "Use the shell tool to run uv commands: sync dependencies, run pytest, build the package, "

Why shell instead of custom tools? Real DevOps work is open-ended — flags change, scripts evolve, and engineers run ad-hoc commands. Wrapping every operation in a @tool function does not scale. Shell middleware lets the agent use the same CLI you would (uv, pytest, bash) while keeping a persistent session so earlier steps (like uv sync) benefit later ones (like uv run pytest).

4. To-Do List Middleware

4.1 What It Does

TodoListMiddleware equips agents with a built-in write_todos tool and system prompts that encourage structured task planning. The agent can create, update, and mark tasks complete — essential for multi-step workflows where progress visibility matters.

4.2 Use Case: Planned Release with Shell Execution

Section 3 ran shell commands directly against invoice-utils. Here we add TodoListMiddleware on top of the same shell setup — but with no extra custom tools. You give a high-level goal; the LLM decides what todos to create, then runs the appropriate uv / shell commands for each one.

Tools available to the agent (all from middleware):

  • write_todos — plan and track steps (added by TodoListMiddleware).
  • Shell tool — execute commands like uv sync, uv run pytest, uv build, deploy scripts (added by ShellToolMiddleware).
Section 3 vs Section 4 Section 3: you tell the agent exactly what commands to run. Section 4: you describe the outcome — the agent plans its own todo list and picks the shell commands.
Your Task

Reuse the invoice-utils folder, project_root, and Windows shell helpers from Section 3. Stack TodoListMiddleware with ShellToolMiddleware — no custom @tool functions. 

from langchain.agents.middleware import TodoListMiddleware, ShellToolMiddleware, HostExecutionPolicy

todo_shell_agent = create_agent(
    model=model,
    tools=[],  # write_todos + shell only — no dummy tools
    middleware=[
        TodoListMiddleware(),
        ShellToolMiddleware(
            workspace_root=str(project_root),
            execution_policy=HostExecutionPolicy(),
            shell_command=r"C:\Program Files\Git\bin\bash.exe",
            env=_shell_environment(),
            startup_commands=["uv --version"],
        ),
    ],
    system_prompt=(
        "You are a release engineer with shell access to a uv-managed Python project. "
        "When given a multi-step goal, first use write_todos to break the work into ordered steps — "
        "you decide what steps are needed. "
        "Execute each todo by running the appropriate shell commands (uv sync, uv run pytest, uv build, "
        "deploy scripts, etc.). "
        "Update todos as you progress and give a final pass/fail summary."
    ),
)

print("Todo + shell agent ready.")
Your Task

Give a high-level release goal — do not list individual commands. Watch the agent create its own todo list, run shell commands for each item, and mark tasks complete.

Why combine todos with shell? Release and onboarding workflows have many steps in a strict order. write_todos keeps the agent from skipping steps or losing track mid-run, while shell commands do the real work — no need to wrap every CLI operation in a custom tool.

5. Combining Middleware (Optional)

Section 4 already stacks TodoListMiddleware with ShellToolMiddleware. In production you often add more layers. Order matters — middleware runs in the order listed. A fuller stack for a release-engineer agent might also include:

  • ShellToolMiddleware — run tests, builds, and deploy scripts.
  • TodoListMiddleware — plan multi-step release work.
  • ToolRetryMiddleware — retry flaky CI API calls.
# Example: stacked middleware for a release engineer (illustrative)
from langchain.agents.middleware import (
    ToolRetryMiddleware,
    TodoListMiddleware,
    ShellToolMiddleware,
    HostExecutionPolicy,
)

release_assistant = create_agent(
    model=model,
    tools=[],  # shell middleware injects its own tool
    middleware=[
        ShellToolMiddleware(
            workspace_root=str(project_root),
            execution_policy=HostExecutionPolicy(),
            shell_command=r"C:\Program Files\Git\bin\bash.exe",
            env=_shell_environment(),
        ),
        TodoListMiddleware(),
        ToolRetryMiddleware(max_retries=2, retry_on=(ConnectionError,)),
    ],
    system_prompt=(
        "You are a senior release engineer. "
        "Run uv/pytest via shell and plan multi-step work with todos."
    ),
)

print("Combined middleware agent configured.")
