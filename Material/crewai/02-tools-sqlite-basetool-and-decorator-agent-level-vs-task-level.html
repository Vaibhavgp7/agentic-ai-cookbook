Let the Coverage Officer Agent Look Things Up

The same Suraksha chat. The contract wording and the old garage notes now live in a small database. The coverage officer agent has to open them before it writes.

How to follow this page. You already have the chat from the previous exercise: one coverage officer agent, one task, and no lookups. Do Step 1 through Step 9 in order. Copy every code block exactly. The code has already been tested. Do not rewrite it. After a step, check what you should see before you continue. New words are explained in parentheses the first time they appear.

The story, in plain words

You are still the claims officer (the human at the keyboard) at Suraksha General Insurance (the made-up car-insurance company). A claim is one customer's accident file. The coverage officer agent (the AI worker that writes a first reading of the file) already writes a coverage opinion (that first reading: "does the contract seem to cover this accident?"). The opinion stays preliminary (a first draft) and non-binding (it does not pay anyone). A senior examiner (a more senior human, not in this chat) still decides the money.

Up to now we were generous. We pasted the policy lines, the office rule, and the older claims straight into the task (the job we assign). A person at a claims desk does not work like that. The accident story arrives in front of them. The policy booklet and the old files sit in the company's records. They have to go and open them.

A tool is a lookup the agent is allowed to call by name. The agent decides when to call it. The tool only reads. It does not decide the claim. We will store the records in a small SQLite database (a single file on disk that holds tables, the way a spreadsheet holds sheets). One tool opens the policy row (the one database line for that claim: the contract wording, the papers, the garage bill, and a review mark). The other opens earlier claims for a garage (the repair shop named in the story). If the row does not contain a fact, the agent must still say it is missing.

Why a tool is the right next step. Exclusion 4 (the contract sentence about a driver with no valid licence) and circular CL-17 (the office rule: a licence that expired within 30 days is sent to a senior examiner, not rejected on the spot) will live only in the policy table. The two older Highway Motors notes will live only in the earlier-claims table. They will not be pasted into the task. If the opinion quotes those lines, the agent opened the database. If we had left them in the task, we would never know whether the agent looked anything up.
These records are made up. The opinion is still for a person to read. The agent must not say the claim has been paid or rejected.

A tool on the agent, or a tool on the task

You can give a tool to the agent (then every job that agent does can use it) or give it to one task (then only that job can use it). Those are different. Read this before you write the files, so you know why the two tools are attached in two places.

Step 2: Policy Record, a class on the agent

In this step you write the lookup that opens one claim's policy row. First create a folder named tools next to crew.jsonc. Inside it, create an empty file tools/__init__.py so Python can import the folder. Then create tools/policy_record.py and paste the block below exactly. This tool is a class that extends BaseTool (CrewAI's built-in starting point for a tool you write as a class). The agent file knows how to build that style: it looks in tools/policy_record.py for a class, and creates one. The name is what the agent sees and decides to call. The description tells the agent when to call it.

import sqlite3
from pathlib import Path

from crewai.tools import BaseTool
from pydantic import BaseModel, Field

DB_PATH = Path(__file__).resolve().parents[1] / "suraksha_claims.db"


class PolicyRecordInput(BaseModel):
    claim_id: str = Field(..., description="The claim id, for example CLM-20481.")


class PolicyRecordTool(BaseTool):
    name: str = "Policy Record"
    description: str = (
        "Reads the policies table for one claim id. "
        "Returns the policy status, the wording that applies, and which papers are on file. "
        "Call this before giving a coverage opinion. Do not guess a clause."
    )
    args_schema: type[BaseModel] = PolicyRecordInput

    def _run(self, claim_id: str) -> str:
        print("Lookup: Policy Record", flush=True)
        with sqlite3.connect(DB_PATH) as conn:
            conn.row_factory = sqlite3.Row
            row = conn.execute(
                "SELECT * FROM policies WHERE claim_id = ?",
                (claim_id.strip().upper(),),
            ).fetchone()
        if row is None:
            return f"No policy record for {claim_id}."
        lines = [f"{key}: {row[key]}" for key in row.keys()]
        return "\n".join(lines)
How to read this file

_run is the function that actually queries (asks) the database. args_schema tells the agent that the only input is a claim id. print writes Lookup: Policy Record in the terminal the moment this tool runs, so you can see the call. flush=True makes that line appear at once. parents[1] steps from the tools folder up to the project folder, where suraksha_claims.db sits. When this step works, both tools/__init__.py and tools/policy_record.py exist.

Step 3: Earlier Claims, a decorated function on this task

In this step you write the lookup for older notes about a garage. Create tools/earlier_claims.py and paste it exactly. This one is a normal function. The line @tool("Earlier Claims") turns that function into a tool. The docstring (the triple-quoted text directly under def) is required: it becomes the description the agent reads. The argument needs a type, here str (text), so CrewAI knows what to pass in.

Do not list this file as custom:earlier_claims. That loader only builds a class. A decorated function is already a finished tool, so we will attach it to this one task in Step 7.

import sqlite3
from pathlib import Path

from crewai.tools import tool

DB_PATH = Path(__file__).resolve().parents[1] / "suraksha_claims.db"


@tool("Earlier Claims")
def earlier_claims(garage_name: str) -> str:
    """Reads the earlier_claims table for one garage name.
    Call this when the accident story names a garage.
    If the garage is not in the table, say so. Do not invent older claims.
    """
    print("Lookup: Earlier Claims", flush=True)
    with sqlite3.connect(DB_PATH) as conn:
        rows = conn.execute(
            """
            SELECT note FROM earlier_claims
            WHERE lower(garage_name) = lower(?)
            ORDER BY id
            """,
            (garage_name.strip(),),
        ).fetchall()
    if not rows:
        return f"No earlier claims on file for garage {garage_name}."
    lines = [f"- {note_text}" for (note_text,) in rows]
    return f"Garage: {garage_name}\n" + "\n".join(lines)

The print writes Lookup: Earlier Claims in the terminal when this tool runs. That line is the check. You do not keep a separate list.

from tools.earlier_claims import earlier_claims


def _get_crew():
    global _crew, _defaults
    if _crew is None:
        _crew, _defaults = load_crew(Path(__file__).parent / "crew.jsonc")
        coverage_task = _crew.tasks[0]
        # This task keeps the policy tool and adds the garage tool.
        # The agent's own list is left unchanged.
        coverage_task.tools = list(coverage_task.tools or []) + [earlier_claims]
    return _crew, _defaults


def claim_to_inputs(claim: dict, officer_question: str) -> dict:
    return {
        "claim_id": claim["claim_id"],
        "narrative": claim["narrative"],
        "officer_question": officer_question,
    }


# ===== CHANGE THIS FUNCTION =====
def respond(user_message: str, claim: dict) -> str:
    """Answer the question. The agent must query the database; the rows are not in the task."""
    crew, defaults = _get_crew()
    inputs = {**defaults, **claim_to_inputs(claim, user_message)}
    result = crew.kickoff(inputs=inputs)
    return result.raw
