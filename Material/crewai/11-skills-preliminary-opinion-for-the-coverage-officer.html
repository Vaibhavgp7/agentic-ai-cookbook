Give the Coverage Officer a Skill

A written procedure in a folder. The officer sees the name first. The full instructions load only when the question needs that procedure.

How to follow this page. Do Step 1, then Step 2, then the small edit in Step 3, then the logging in Step 4, then run skill_check.py in Step 5 before you trust the claims chat. Copy the skill file and the check files exactly. The code has already been tested. The skill mark SKILL MARK: PRELIMINARY-OPINION is the proof the procedure was loaded. If that line is missing, the body was not loaded. New words are explained in parentheses the first time they appear.

The story, in plain words

The coverage officer already knows two kinds of help. Knowledge (the claims manual) is facts, retrieved in pieces. Tools (Policy Record and Earlier Claims) are functions the model can call. A skill is neither. It is a written procedure (a checklist of how to shape the preliminary opinion). The opinion is still a first reading. It still must not say the claim is paid or declined.

You will put that procedure in a folder. At the start, the officer sees only the name and a one-line description. The full instructions load only when the question is actually an opinion. A question such as "what is two plus two?" must not load them.

CrewAI reads skills from the filesystem (the folders on your computer). Each skill is a directory (a folder). The required file is SKILL.md. The top of that file is YAML (a small block of name: and description: lines) between two --- lines. That block is the frontmatter (the label at the top). The markdown under it is the procedure.

The path you put on the agent is a search folder, not the skill folder itself. From suraksha_claims_desk, skills is that folder. CrewAI looks inside each subdirectory for SKILL.md. It finds skills/preliminary-opinion/SKILL.md. If you point skills at skills/preliminary-opinion, it looks inside that folder for another skill directory and finds none.

The body is not in the first prompt. At setup the officer receives the skill name and the description. That is disclosure level 1 (the name and the one-line description only; the full procedure is not in the prompt yet). The body stays out until the model calls the built-in tool load_skill (a tool CrewAI adds for you; you do not write it) with the exact name preliminary-opinion. The tool returns the body for that execution. That is disclosure level 2 (the full procedure, loaded for this task only). The next question does not keep it. An activated Skill object, passed from Python, would be always-on. This page does not do that.
allowed-tools does not add tools. That frontmatter field is experimental metadata. Policy Record stays on the agent file, under tools. The skill does not open the database by itself.

Where you are working

Stay inside suraksha_claims_desk. This page adds the skill directory, the skills field on the coverage officer, the first step of the coverage task in crew.jsonc, skill logs in desk.py, a small check crew, and skill_check.py. Leave the flow, app.py, and the mail clerk as they are.

The skill is on the coverage officer, so the claims chat uses it whenever that officer runs. The examiner brief writer does not get it. A skills list on crew.jsonc would apply to every agent. Agent-level skills win when the same name appears in both places. This page keeps the list on the officer only.

Step 1: Write the procedure

In this step you create the folder and the procedure file. The folder name and the name inside the file must both be preliminary-opinion. Copy the block exactly, including the skill mark. That line appears nowhere else. If an answer contains it, the procedure was loaded.

Create skills/preliminary-opinion/SKILL.md

The directory name and the name field must be the same: lowercase letters, digits, and hyphens. The description says when to use the skill. The body holds a line that appears nowhere else: SKILL MARK: PRELIMINARY-OPINION. If that line shows up in an answer, the body was loaded.

---
name: preliminary-opinion
description: Use this when writing a preliminary coverage opinion for a Suraksha claim. It is the procedure for that opinion. Do not use it for arithmetic, mail, or a question that does not ask for an opinion.
metadata:
  author: suraksha-desk
  version: "1.0"
---

## Preliminary opinion procedure

This is a procedure, not a fact from the claims manual and not a database tool.

When you write the opinion:

1. Call Policy Record before you quote a clause.
2. Do not say the claim is paid, approved, or declined.
3. Put this exact line on its own, after the first heading:

SKILL MARK: PRELIMINARY-OPINION

That line is the proof the procedure was loaded. Do not invent a different mark.

Optional folders next to SKILL.md are scripts/, references/, and assets/. This page does not use them. They are catalogued only if you promote the skill to disclosure level 3 in Python with load_resources. load_skill stops at the body.

Step 4: Log the skill on the claims desk

In this step you add print lines so the terminal tells you whether the procedure was found, whether its body is still unloaded, and whether the chat note contains the skill mark. Follow the green boxes in order. Do not change the flow or the mail clerk.

Add the listener and the ready line in desk.py

Add _skill_logs_on = False and _listen_for_skills above _get_crew. Call the listener before load_crew, and print Skill ready: after the officer is configured. These lines run once, the first time a complex file builds the crew.

_skill_logs_on = False


def _listen_for_skills() -> None:
    """Print skill discovery and load_skill. Once per process."""
    global _skill_logs_on
    if _skill_logs_on:
        return
    _skill_logs_on = True
    from crewai.events.event_bus import crewai_event_bus
    from crewai.events.types.skill_events import (
        SkillDiscoveryCompletedEvent,
        SkillUsedEvent,
    )

    @crewai_event_bus.on(SkillDiscoveryCompletedEvent)
    def _on_skills_found(source, event) -> None:
        print(
            f"Skill found: {', '.join(event.skill_names)} in {event.search_path}",
            flush=True,
        )

    @crewai_event_bus.on(SkillUsedEvent)
    def _on_skill_used(source, event) -> None:
        print(
            f"Skill used: {event.skill_name}. Disclosure level {event.disclosure_level}.",
            flush=True,
        )


def _get_crew():
    global _crew, _defaults
    if _crew is None:
        _listen_for_skills()
        manuals = _open_manuals()
        _crew, _defaults = load_crew(Path(__file__).parent / "crew.jsonc")
        coverage_officer = _crew.agents[0]
        # The manager hands this agent a fresh task.
        # A tool pinned only to coverage_opinion does not travel with that handoff.
        coverage_officer.tools = list(coverage_officer.tools or []) + [earlier_claims]
        # crew.jsonc must not list knowledge_sources. An empty list here
        # keeps a later question from embedding the files again.
        coverage_officer.knowledge_sources = []
        if manuals is not None:
            coverage_officer.knowledge = manuals
        ready = list(coverage_officer.skills or [])
        if not ready:
            print("Skill ready: none on the coverage officer.", flush=True)
        for skill in ready:
            print(
                f"Skill ready: {skill.name}. Disclosure level {skill.disclosure_level}.",
                flush=True,
            )
    return _crew, _defaults

Create skill_check.py

Save this next to desk.py. The two handlers are the log. Skill found: is discovery. Skill ready: prints disclosure level 1, which means the body is not loaded yet. Skill used: prints when load_skill returns the body. Level 2 is that body.

from pathlib import Path

from dotenv import load_dotenv
from crewai.events.event_bus import crewai_event_bus
from crewai.events.types.skill_events import (
    SkillDiscoveryCompletedEvent,
    SkillUsedEvent,
)
from crewai.project import load_crew

load_dotenv()

HERE = Path(__file__).resolve().parent


@crewai_event_bus.on(SkillDiscoveryCompletedEvent)
def _on_skills_found(source, event) -> None:
    print(
        f"Skill found: {', '.join(event.skill_names)} in {event.search_path}",
        flush=True,
    )


@crewai_event_bus.on(SkillUsedEvent)
def _on_skill_used(source, event) -> None:
    print(
        f"Skill used: {event.skill_name}. Disclosure level {event.disclosure_level}.",
        flush=True,
    )


if __name__ == "__main__":
    print(
        "Skill check: loading skill_crew.jsonc. The claims chat is not started.",
        flush=True,
    )
    crew, defaults = load_crew(HERE / "skill_crew.jsonc")
    officer = crew.agents[0]
    for skill in officer.skills or []:
        print(
            f"Skill ready: {skill.name}. Disclosure level {skill.disclosure_level}.",
            flush=True,
        )
    result = crew.kickoff(inputs=defaults)
    for task_output in result.tasks_output:
        print(f"\nTask {task_output.name}:\n{task_output.raw}", flush=True)

  • A skill is instructions. A tool is a function. Knowledge is retrieved facts. This officer now has all three, and they are configured separately.
  • skills on the agent file is a list of search folders, inline SKILL.md text, or @org/name registry references. This page uses the folder skills.
