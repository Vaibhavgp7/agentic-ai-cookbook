Let the Mail Clerk Use Gmail

A separate worker. It does not join the claims team. It drafts one note in your Gmail, then sends one practice message to you.

How to follow this page. This page does not change the claims chat. Do not add the mail clerk to crew.jsonc, and do not call it from respond. A question about cover must not send mail. Do Step 1, then the Google sign-in in Step 2, then copy the files in Step 4 exactly. Before you run Step 5, set my_email to your own Gmail address. The code has already been tested. New words are explained in parentheses the first time they appear.

The story, in plain words

The claims desk can already write a note that says the police report on CLM-10044 is missing. Nobody has mailed that note. On this page you add a mail clerk (a separate AI worker whose only job is email). It drafts one message about that missing report, and then it sends one short lab message to you, so you can see the send in your own inbox. It does not pay or decline any claim. It is not part of the claims crew.

You have already given the coverage officer tools that you wrote: Policy Record and Earlier Claims. Those tools live in the same Python project. The agent calls them, and your function reads SQLite (the claims database file).

MCP (a way for the agent to use tools that live in another program) is how the mail clerk reaches Gmail. That other program is an MCP server (a program that starts, announces the tools it offers, and waits). CrewAI is the client (the side that asks). When the model chooses a tool, CrewAI sends the arguments to the server and brings the result back. You do not write the Gmail function. The server already has it.

This server runs on your machine and speaks through standard input and output (the text a program reads and the text it prints). That style is called stdio. CrewAI starts it with a command and a list of arguments, the same way a terminal would. The command here is npx (a Node.js command that runs a package). The package is @gongrzhe/server-gmail-autoauth-mcp. The -y flag lets Python start the package without asking you to confirm the download.

A remote MCP server is different. You would put an https:// address in the agent's mcps list, as a plain string. Google hosts one at https://gmailmcp.googleapis.com/mcp/v1 for projects in the Workspace Developer Preview. That hosted server can create a draft. This page uses the local npx server, because the same sign-in can create a draft and send a message.

The name the model sees is long. CrewAI builds the tool name from the command, the arguments, and the server's own tool name. In the terminal you will see a long name that ends with draft_email, send_email, or search_emails. The last part is the real tool. The task text below tells the agent to use the tool by that ending.
This agent can send real email from your Gmail account. Set my_email in mail_crew.jsonc to your own address. Leave delete_email off the agent. The mail clerk is a separate run. Do not add it to crew.jsonc, and do not call it from respond. A question about cover must not send mail.

Where you are working

Stay inside suraksha_claims_desk. Stop the claims chat with Ctrl+C if it is open. On Windows PowerShell, set this once in that terminal:

$env:PYTHONUTF8="1"

Leave the claims crew, the flow, and app.py as they are. This page adds three files: agents/mail_clerk.jsonc, mail_crew.jsonc, and a short mail_note.py that only loads that crew. Do not put the mail clerk in crew.jsonc.

Step 1: Node.js

In this step you install Node.js (the program that can start the Gmail server). The Gmail server is an npm package (a published JavaScript program). You need Node.js 18 or newer. When this step works, both commands below print a version number.

  1. Open nodejs.org and install the Windows LTS build. Leave "Add to PATH" selected.
  2. Close the terminal and open a new one, so it sees the new PATH.
  3. Check:
node --version
npx --version

Both commands should print a version. If npx is not found, the installer did not update PATH. Open a new terminal after the install.

Step 2: Let Google sign the server in as you

In this step you let the server act as your Gmail account. You sign in once in the browser. After that, a token (a saved permission) sits on disk and later runs reuse it. Follow the small lists below in order. Do not skip the test-user step. While the app is in testing, Google blocks every address you did not add. OAuth (the sign-in that lets this app use Gmail without you typing your password into Python) is what this step sets up.

If you already completed a Gmail MCP sign-in on this PC, you already have %USERPROFILE%\.gmail-mcp\gcp-oauth.keys.json and %USERPROFILE%\.gmail-mcp\credentials.json. Skip to Step 3.

Google Cloud project

  1. Open console.cloud.google.com.
  2. Create a project. A name such as suraksha-gmail-lab is enough. Select that project.
  3. APIs and Services, Library. Search Gmail API. Enable it.
  4. APIs and Services, OAuth consent screen. Get started. App name Gmail Agent. User support email: yours. User type External. Finish the contact step and create the screen.
  5. Data Access, or Scopes on an older console. Add or remove scopes. Under manually add scopes, add these two, then update and save:
    • https://www.googleapis.com/auth/gmail.modify
    • https://www.googleapis.com/auth/gmail.settings.basic
    The first scope is what lets the server read, draft, and send. The second is what the package asks for on the first sign-in.
  6. APIs and Services, Credentials. Create credentials, OAuth client ID. Application type Desktop app. Name it Gmail Agent Desktop. Download the JSON and save it as credentials.json.
  7. OAuth consent screen, Audience. Add users. Add the Gmail address you will sign in with. While the app is in testing, only those addresses can approve the prompt.

Put the client file where this server looks

This package reads gcp-oauth.keys.json from a folder named .gmail-mcp under your user profile. From the folder that contains credentials.json:

New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.gmail-mcp"
Copy-Item .\credentials.json "$env:USERPROFILE\.gmail-mcp\gcp-oauth.keys.json"
Keep those files secret. credentials.json, gcp-oauth.keys.json, and the token written in the next command are passwords for your Google project. Do not commit them. Do not paste them into the chat.

Sign in once

npx -y @gongrzhe/server-gmail-autoauth-mcp auth

A browser opens. Sign in with the test-user address and allow access. The server writes the token to %USERPROFILE%\.gmail-mcp\credentials.json. You do this once. Later runs refresh the token when it expires. This command also downloads the package, so the crew's first start is less likely to time out.

Step 3: What the mail clerk is allowed to call

The package offers many tools. This lab keeps three.

Server toolWhat it doesArguments you care about
draft_emailCreates a draft. Nothing is sent.to is a list of addresses, plus subject and body.
send_emailSends immediately.The same to, subject, and body.
search_emailsSearches with Gmail query words.A query such as from:me newer_than:1d.

delete_email is a tool on the same server. It is absent from the allow list, so the agent never receives it.

On the agent, the field is mcps. One item is one server. A local server is an object with command and args. When the agent file is loaded, that object becomes MCPServerStdio. CrewAI starts that process when the agent is about to work, asks for the tool list, wraps each allowed tool, and closes the process when the call is finished. The next tool call starts a fresh process, so two calls do not share one connection.

The allow list sits in the same object, under tool_filter. Set type to static and list allowed_tool_names. The loader turns that object into the same filter a Python file would build with create_static_tool_filter. A JSON file cannot hold an arbitrary Python function. It can hold this static list. The claims crew in crew.jsonc stays as it is. The mail clerk has its own crew file.

Step 4: Write the mail clerk in configuration

In this step you add three files and you do not touch the claims crew. Before you save mail_crew.jsonc, replace you@gmail.com with your own Gmail address. The tasks mail only that address.

Create agents/mail_clerk.jsonc

Save this next to the other agent files. mcps is the Gmail server. The loader reads command and args as a stdio server, then builds the allow list from tool_filter.

{
  "role": "Mail clerk at Suraksha General Insurance",
  "goal": "Use Gmail only for the message written in the task, and only to the address written in the task.",
  "backstory": "You prepare mail for a claims officer at Suraksha in India. You never say a claim is paid, approved, or declined. You never delete mail. You never write to an address that is absent from the task.",
  "llm": "openai/gpt-4o-mini",
  "mcps": [
    {
      "command": "npx",
      "args": ["-y", "@gongrzhe/server-gmail-autoauth-mcp"],
      "tool_filter": {
        "type": "static",
        "allowed_tool_names": ["draft_email", "send_email", "search_emails"]
      }
    }
  ],
  "settings": {
    "verbose": true,
    "allow_delegation": false,
    "max_iter": 8
  }
}
Create mail_crew.jsonc

Save this next to crew.jsonc. It is a second crew, not a change to the claims crew. Change my_email to your own Gmail address before you run it. {my_email} in a task is filled from inputs at kickoff. Two tasks run in order. The first may only draft. The second may only send, and only to that same address.

{
  "name": "Suraksha Mail Clerk",
  "agents": ["mail_clerk"],
  "tasks": [
    {
      "name": "draft_the_note",
      "agent": "mail_clerk",
      "description": "Create one Gmail draft. Do not send it.\nTo: {my_email}\nSubject: CLM-10044 police report still missing\nBody: The Necklace Road file CLM-10044 is waiting. The police report is not on file. This note does not pay or decline the claim.\nCall the tool whose name ends with draft_email. to must be a list containing only that address.\nDo not call a tool whose name ends with send_email.",
      "expected_output": "One short paragraph. Say the draft was created and was not sent. Repeat the subject."
    },
    {
      "name": "send_the_lab_check",
      "agent": "mail_clerk",
      "description": "Send one email now.\nTo: {my_email}\nSubject: Suraksha lab mail check\nBody: This message was sent by the Suraksha mail clerk through the Gmail MCP server. It is a lab message. It does not pay or decline any claim.\nCall the tool whose name ends with send_email. to must be a list containing only that address.\nDo not delete anything.",
      "expected_output": "One short paragraph. Say the message was sent. Repeat the subject."
    }
  ],
  "process": "sequential",
  "verbose": true,
  "inputs": {
    "my_email": "you@gmail.com"
  }
}
Create mail_note.py

Save this next to desk.py. It does not build an agent. load_crew reads mail_crew.jsonc, finds agents/mail_clerk.jsonc, and returns the crew plus the inputs.

from pathlib import Path

from dotenv import load_dotenv
from crewai.project import load_crew

load_dotenv()

HERE = Path(__file__).resolve().parent


if __name__ == "__main__":
    print(
        "Mail clerk: loading mail_crew.jsonc. The claims crew is not used.",
        flush=True,
    )
    crew, defaults = load_crew(HERE / "mail_crew.jsonc")
    print(
        f"Mail clerk: draft and send only to {defaults['my_email']}.",
        flush=True,
    )
    result = crew.kickoff(inputs=defaults)
    print(result.raw)

The first time Python says the MCP library is missing, add it inside the project and run again:

uv add mcp

CrewAI already expects that library. The line is only for a project where the import fails.

Step 5: Run it and open Gmail

In this step you run the mail clerk once, then open Gmail. Stay inside suraksha_claims_desk. The first task should create a draft and must not send it. The second task should send one message to you. When it works, Gmail Drafts contains the CLM-10044 note, and your inbox contains the lab check.

uv run python mail_note.py

The terminal starts with Mail clerk: loading mail_crew.jsonc. The claims crew is not used. and then names the address from inputs. The first task should call the tool that ends with draft_email. The printed answer should say the draft was created and was not sent. The subject is CLM-10044 police report still missing. The body says the police report is not on file, and it does not pay or decline the claim.

The second task should call the tool that ends with send_email. The subject is Suraksha lab mail check. The last thing printed is that second answer, because a sequential crew returns the last task.

Open Gmail. Drafts should contain the CLM-10044 note. Sent, and your inbox, should contain the lab check, because you mailed yourself. If the draft is missing, the first task called the send tool or called nothing. Read the terminal for the tool name that actually ran.

If Windows cannot start npx

Some Windows setups only have npx.cmd, and starting npx from Python fails. In agents/mail_clerk.jsonc, change "command": "npx" to "command": "npx.cmd" and run the file again. Use the same command that works in your terminal for the auth step.

The static filter keeps three. │ ▼ Task 1 calls the tool that ends with draft_email │ ▼ Task 2 calls the tool that ends with send_email │ ▼ Gmail shows a draft and a message to you
  • MCP means the tool runs in another program. Stdio means CrewAI starts that program and talks on its input and output.
  • mcps on the agent file is the list of servers. A local server is an object with command and args. The loader turns that object into MCPServerStdio. A remote server is an https:// string.
  • tool_filter with "type": "static" and allowed_tool_names is the allow list. The names are draft_email, send_email, and search_emails. The model sees those names with a long prefix. The task tells it to match the ending.
  • The claims desk is untouched. This crew is mail_crew.jsonc. mail_note.py only loads it.
