The story, in plain words

You are still the claims officer (the human at the keyboard). Three files need three different treatments. CLM-10021 is a small complete parking scrape: a checklist can describe it, and nobody should wait for an AI opinion. CLM-10044 is a small scrape with a missing police report: the desk should ask for the paper and stop. CLM-20481 is the hard file: the customer and the police disagree, the licence expired 12 days earlier, and the garage bill is far over ₹25,000. That file still needs the crew (the coverage officer and the brief writer).

You already have claim_route.py. That file can print settle_by_rule (checklist), wait_for_papers (stop and ask for the missing paper), or ask_the_crew (wake the AI team). The chat does not call it yet. Every question still starts the crew.

This page connects them. The chat will call a flow (a Python class whose methods run in an order you declare). It is not a third agent, and it is not written in crew.jsonc. You write the flow yourself, because the procedure includes doors that never call a model. A door here is one of those three paths. The words you type do not choose the door. The policy row does.

The four methods

Read this table before you paste the code, so the names are familiar. A flow starts when you call kickoff (the command that begins the procedure). You can pass a dictionary (a set of named values). Every key that matches a field on the flow's state (the small form the methods share) is copied onto that state before the first method runs. Our state holds the claim id, the question, the door, and the answer. A decorator (the @ line above a function) tells CrewAI when that function is allowed to run.

DecoratorMethod in this deskWhat it does
@start()read_the_fileRuns first. Calls route_claim and stores the label on self.state.route. Returns that label.
@router(read_the_file, emit=[...])choose_doorRuns because read_the_file finished. Receives the label, because the method takes one argument besides self. Returns the same label. Returning the label is what emits it. emit lists the three labels for the picture.
@listen("settle_by_rule")handle_rulesRuns only when the router returns that exact string. Writes the rules sentence. Does not call the crew.
@listen("wait_for_papers")handle_missing_papersSame idea for a missing paper.
@listen("ask_the_crew")handle_complex_claimCalls run_crew. That is the old body of respond.

Only one listener runs. kickoff returns whatever that listener returns. The other two are skipped, not run and then ignored.

emit on the router lists the three labels in advance. The picture you will draw of the flow uses that list. If you forget emit, the methods still work as long as they return those strings, but the picture may not show the branches.

The method name and the label are different strings. handle_complex_claim listens for ask_the_crew. It is not named ask_the_crew. When a method finishes, its name is also an event. If the name and the label match, the method hears itself and starts again. CrewAI then raises a recursion error and tells you the label matched the method's own name.
Two functions, on purpose. run_crew loads the crew and returns the opinion plus the brief. respond is what the chat calls. respond starts the flow. The complex door calls run_crew. If the complex door called respond, the flow would start another flow. Import both inside the functions, not at the top of both files. If each file imports the other at the top, Python cannot finish loading either one.

def run_crew(user_message: str, claim: dict) -> str:
    """Run the crew. The flow calls this only for a complex file."""
    print(
        f"Crew start: {claim['claim_id']}. Question: {user_message}",
        flush=True,
    )
    crew, defaults = _get_crew()
    # The first kickoff builds a manager that has tools.
    # A second kickoff refuses to run until that manager is cleared.
    crew.manager_agent = None
    inputs = {**defaults, **claim_to_inputs(claim, user_message)}
    result = crew.kickoff(inputs=inputs)
    labels = {
        "coverage_opinion": "Coverage opinion",
        "examiner_brief": "Examiner brief",
    }
    parts = []
    for task_output in result.tasks_output:
        heading = labels.get(task_output.name, task_output.name or "Task")
        parts.append(f"## {heading}\n\n{task_output.raw}")
    return "\n\n".join(parts)


def respond(user_message: str, claim: dict) -> str:
    """The chat calls this. The flow chooses the door before any agent starts."""
    from desk_flow import DeskFlow

    print(
        f"Chat: {claim['claim_id']}. Starting a flow. The crew has not started.",
        flush=True,
    )
    answer = DeskFlow().kickoff(
        inputs={
            "claim_id": claim["claim_id"],
            "officer_question": user_message,
        }
    )
    if not isinstance(answer, str):
        return str(answer)
    return answer

Save this next to desk.py. The first line of every answer is DESK ROUTE: and the label. That line is how you, and the chat, can see which door opened. The Desk: lines are the terminal log. Search for them when the Flow boxes are noisy. One listener prints. The other two do not.

from pydantic import BaseModel

from crewai.flow.flow import Flow, listen, router, start

from claim_route import policy_row, route_claim


class DeskState(BaseModel):
    claim_id: str = ""
    officer_question: str = ""
    route: str = ""
    answer: str = ""


class DeskFlow(Flow[DeskState]):
    @start()
    def read_the_file(self) -> str:
        label = route_claim(self.state.claim_id)
        self.state.route = label
        print(
            f"Desk: {self.state.claim_id} read the file. Label is {label}.",
            flush=True,
        )
        return label

    @router(
        read_the_file,
        emit=["settle_by_rule", "wait_for_papers", "ask_the_crew"],
    )
    def choose_door(self, decision: str) -> str:
        if decision not in ("settle_by_rule", "wait_for_papers", "ask_the_crew"):
            print(
                f"Desk: {decision!r} is not a door. Opening ask_the_crew.",
                flush=True,
            )
            self.state.route = "ask_the_crew"
            return "ask_the_crew"
        print(f"Desk: choose_door returns {decision}.", flush=True)
        return decision

    @listen("settle_by_rule")
    def handle_rules(self) -> str:
        print(
            f"Desk: {self.state.claim_id} settle_by_rule. The crew was not called.",
            flush=True,
        )
        row = policy_row(self.state.claim_id)
        estimate = int(row["estimate_inr"])
        limit = int(row["simple_pay_limit_inr"])
        self.state.answer = (
            f"DESK ROUTE: settle_by_rule\n\n"
            f"RULES CHECK — NOT A CREW OPINION\n\n"
            f"Claim {self.state.claim_id} is a complete own-damage file. "
            f"The estimate is INR {estimate}, which is within the simple-pay limit of INR {limit}. "
            f"The policy row does not mark it REVIEW, and the papers do not say NOT ON FILE. "
            f"A rules settlement can be prepared. This chat does not move money. The crew was not called."
        )
        return self.state.answer

    @listen("wait_for_papers")
    def handle_missing_papers(self) -> str:
        print(
            f"Desk: {self.state.claim_id} wait_for_papers. The crew was not called.",
            flush=True,
        )
        row = policy_row(self.state.claim_id)
        self.state.answer = (
            f"DESK ROUTE: wait_for_papers\n\n"
            f"WAITING FOR PAPERS\n\n"
            f"Claim {self.state.claim_id} is not ready for an opinion. "
            f"The policy row says: {row['papers_on_file']} "
            f"The crew will not read this file until that paper is here. "
            f"Do not treat the estimate as payable."
        )
        return self.state.answer

    @listen("ask_the_crew")
    def handle_complex_claim(self) -> str:
        print(
            f"Desk: {self.state.claim_id} ask_the_crew. Calling the crew.",
            flush=True,
        )
        from sample_claims import CLAIMS
        from desk import run_crew

        claim = CLAIMS[self.state.claim_id]
        body = run_crew(self.state.officer_question, claim)
        self.state.answer = f"DESK ROUTE: ask_the_crew\n\n{body}"
        return self.state.answer


if __name__ == "__main__":
    flow = DeskFlow()
    print(flow.plot("suraksha_desk_flow.html", show=False))
    runs = (
        ("CLM-10021", "Is this loss covered?"),
        ("CLM-10044", "Is this loss covered?"),
        ("CLM-20481", "Is this loss covered?"),
        ("CLM-10021", "Should we pay this claim now?"),
        ("CLM-10044", "What is the chassis number?"),
    )
    for claim_id, question in runs:
        print("\n" + "=" * 20, claim_id, "|", question)
        answer = DeskFlow().kickoff(
            inputs={
                "claim_id": claim_id,
                "officer_question": question,
            }
        )
        print(answer)

What just happened

Chat calls respond │ ▼ DeskFlow.kickoff copies claim_id and officer_question onto the state │ ▼ read_the_file stores the label from route_claim │ ▼ choose_door returns that label │ ├── handle_rules no crew ├── handle_missing_papers no crew └── handle_complex_claim run_crew, then both headings
  • @start is the entry. @router runs when that method finishes and emits one label. @listen runs only for its label.
  • State is the small form the methods share. kickoff(inputs=...) fills fields of the same name. The listener reads self.state. It does not need the label as an argument, because the label already selected which method runs.
  • The crew is unchanged. The flow is the new outer procedure. Simple files and missing papers never reach kickoff on the crew.
  • The first line DESK ROUTE: is part of the answer so you can see the door in the chat. The Desk: lines are the same fact in the terminal. Crew start: is the only line that means the crew ran.
What this flow does not do

It does not pause for a person. A complex answer still ends when the brief is written. It does not pay. It does not replace Policy Record. If the crew has memory or a claims manual, those still belong to the crew and are used only on the complex door, because that is the only door that starts the crew.
