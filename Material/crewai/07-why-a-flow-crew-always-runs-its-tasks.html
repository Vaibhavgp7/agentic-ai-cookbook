Why the Desk Needs a Flow

The team can write an opinion. It cannot decide that this file should never have been given to the team.

How to follow this page. You already have a chat that sends every claim to the crew. On this page you only add one new Python file and run it. Do not change the chat. Copy claim_route.py exactly. When the script prints the three labels below, the step has worked. New words are explained in parentheses the first time they appear.

The story, in plain words

You are still the claims officer (the human at the keyboard) at Suraksha, the made-up car insurer. A claim is one accident file. The crew (the AI team: the coverage officer who writes the first reading, and the brief writer who turns that reading into a short note) already runs for every question. A senior examiner (a person outside the chat) is still the only one who can pay or refuse.

That was the right shape while you were teaching the crew to read. It is the wrong shape for a claims desk. Open CLM-10021 and ask whether the loss is covered. You will wait while two agents discuss a parking scrape of ₹18,000 whose papers are already complete. Open CLM-10044 and they will write an opinion while the police report is still missing. A person at the desk would not do either of those things. A small complete file can be described by a checklist. A file with a missing paper should wait. Only a hard file should wake the crew.

What a crew can and cannot do

A crew is a team with a list of tasks. You choose how the team works.

In a sequential crew (tasks run in the order they are written) the agent named on a task does that task. The second task can read the first because its context (the list of earlier answers it may read) lists the first task's name.

In a hierarchical crew (a manager hands each task to a specialist), CrewAI adds a Crew Manager. The tasks are still the tasks you wrote. The manager does not look at the file and say "do not start."

Either way, kickoff (the command that starts the crew) means: do this work. There is no setting on the crew that means "if the police report is missing, do nothing." You can tell an agent, inside a task, to mention a missing paper. The agent still ran. The model was still called. The brief was still written. The desk has already spent the time.

A flow is the procedure around the team. A flow is ordinary Python that runs before any agent. It reads the file and chooses a door. One door can call the crew. The other doors return a sentence and stop. The crew stays what it is. The flow decides whether the crew is needed.

The three doors

The choice is not a judgement the model should invent. It is already written in suraksha_claims.db, in the policies table. A policy row is the one database line for that claim. setup_claims_db.py put these columns there: papers_on_file (which documents are present), rules_mark (a review flag; REVIEW means a person should read the file), injury (whether anyone was hurt), estimate_inr (the garage bill in rupees), and simple_pay_limit_inr (the largest bill a checklist may pass; on every row here that limit is 25000, which is ₹25,000).

Read the row in this order. The order is the rule. A later line must not override an earlier one.

  1. Wait for papers, label wait_for_papers. If papers_on_file contains the words NOT ON FILE, stop. CLM-10044 says the police report is not on file. The estimate is ₹22,000, which is under the limit, and that does not matter. A missing paper wins.
  2. Ask the crew, label ask_the_crew. If rules_mark contains REVIEW, or if estimate_inr is greater than simple_pay_limit_inr, the file is not a rules file. CLM-20481 is marked REVIEW and the estimate is ₹1,85,000. Exclusion 4 (the contract sentence about a driver with no valid licence), circular CL-17 (the office rule: a licence that expired within 30 days is sent to a senior examiner, not rejected on the spot), the disagreeing reports, and the Highway Motors notes are why a coverage officer has to read it. The door only decides to call them. It does not write the opinion.
  3. Settle by rule, label settle_by_rule. If the injury is none and the estimate is within the limit, a rules check (a fixed checklist, with no AI opinion) can describe the file. CLM-10021 is that file: complete papers, no injury, ₹18,000, licence effective (the driver was allowed to drive), rules_mark none. The message may say a rules settlement can be prepared (the file is eligible for the company's ordinary small-claim process). It must not say the money has moved.
  4. Anything that matches none of those, including a claim id with no row, uses ask_the_crew. When you are unsure, a person and the crew should see the file. A silent rules payment should not.
Do not ask an agent which door to open. An agent is for wording that has to be interpreted: Exclusion 4 beside CL-17, a customer report beside a police report. "Does this text contain NOT ON FILE?" is a question Python answers exactly. If you spend a model call on it, the agent can misread the row, and you have lost the reason for having a rule.

Where a flow will sit

You are not building the flow on this page. You are proving the three labels, because a flow is only as good as the choice it makes.

When you do build it, the shape is a Python class (a blueprint with methods). One method is the start: it reads the claim and stores the label. A router method (the method that returns one short label) returns that label and nothing else. Three listener methods (methods that run only when their label comes back) wait, each for one label. Kickoff runs the start, then the router, then only the listener whose label came back. The other two listeners do not run. The value kickoff returns is whatever that one listener returns.

Two details matter so the class does not surprise you later.

  • The listener's Python name must not be the same as the label it waits for. If a method is named ask_the_crew and it also listens for ask_the_crew, finishing the method emits that name again, and the method starts itself. CrewAI stops that loop after a fixed number of calls. Name the method for the work, such as handle_complex_claim, and keep the label as ask_the_crew.
  • The chat must keep calling respond. Later, respond will call the flow, and only the complex door will call the crew. If the flow calls respond, and respond calls the flow, they call each other forever. The crew runner and the desk procedure have to be two functions.

None of that is wired today. The chat still calls the crew for every claim. You should see that contrast with your own run.

Step 1: Read the row and name the door

Create claim_route.py

Save this file in the project folder, next to desk.py. It only reads SQLite. It does not import CrewAI and it does not call a model.

import sqlite3
from pathlib import Path

DB_PATH = Path(__file__).resolve().parent / "suraksha_claims.db"


def policy_row(claim_id: str) -> sqlite3.Row | None:
    with sqlite3.connect(DB_PATH) as conn:
        conn.row_factory = sqlite3.Row
        return conn.execute(
            "SELECT * FROM policies WHERE claim_id = ?",
            (claim_id.strip().upper(),),
        ).fetchone()


def route_claim(claim_id: str) -> str:
    """Choose a door from the policy row. Do not call a model."""
    row = policy_row(claim_id)
    if row is None:
        return "ask_the_crew"

    papers = (row["papers_on_file"] or "").upper()
    mark = (row["rules_mark"] or "").upper()
    injury = (row["injury"] or "").strip().lower()
    estimate = int(row["estimate_inr"])
    limit = int(row["simple_pay_limit_inr"])

    if "NOT ON FILE" in papers:
        return "wait_for_papers"
    if "REVIEW" in mark or estimate > limit:
        return "ask_the_crew"
    if injury == "none" and estimate <= limit:
        return "settle_by_rule"
    return "ask_the_crew"


if __name__ == "__main__":
    for claim_id in ("CLM-10021", "CLM-10044", "CLM-20481"):
        row = policy_row(claim_id)
        print(claim_id, route_claim(claim_id))
        print("  papers:", row["papers_on_file"])
        print("  rules_mark:", row["rules_mark"])
        print("  estimate:", row["estimate_inr"], "limit:", row["simple_pay_limit_inr"])
        print()
