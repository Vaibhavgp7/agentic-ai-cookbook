Two Agents, One After the Other

The same Suraksha chat. The coverage officer still writes the opinion. A second AI worker then writes the short note a senior person will read.

How to follow this page. You already have one coverage officer agent, two lookups (Policy Record and Earlier Claims), and a chat. Do the steps in order. Copy every code block exactly. The code has already been tested. Do not rewrite it. After a step, check what you should see before you continue. New words are explained in parentheses the first time they appear.

The story, in plain words

You are still the claims officer (the human at the keyboard). The coverage officer agent (the AI worker that reads the file) already writes a coverage opinion (a first reading of whether the contract seems to cover the accident). That opinion is preliminary (a first draft) and non-binding (it does not pay anyone). A senior examiner (a more senior human, not in this chat) is still the only person who can pay or refuse.

Right now one agent does two kinds of writing. It opens the records, decides what the contract sentences mean, and also prepares the note a senior examiner would pick up. At a real desk those are two people in a line. The first person finishes the opinion. The second person starts only after that opinion exists, and writes a short brief (a one-page summary for the meeting). The second person does not walk back to the records room.

We will add that second person as a second agent, the examiner brief agent. It is not the senior examiner. It only writes the brief. The crew (the team of agents and tasks, run together) will run two tasks, in order. CrewAI calls that order a sequential process (the first task runs to the end, then the second task starts). The second task is handed the first task's answer through a field named context (the list of earlier answers this task is allowed to read).

The brief writer is not the senior examiner. You are still the human at the chat. The coverage officer agent reads the file. The examiner brief agent turns that opinion into a short brief. A senior examiner, a person, still decides every payment and every denial. Neither agent may say the claim is paid or rejected.

How the names connect

"agents" loads both agent files. Each task has its own "agent". "context": ["coverage_opinion"] works only because the first task is named coverage_opinion and is written above the brief task. CrewAI refuses a context name it has not seen yet. The coverage opinion is saved to output/coverage_{claim_id}.md. The brief is saved to output/brief_{claim_id}.md. "tracing": true records the run so you can open it afterwards. The steps for signing in and reading that record are after you have seen the crew run once.

Replace respond

Keep _get_crew and claim_to_inputs. Replace respond with this.

def respond(user_message: str, claim: dict) -> str:
    """Run both tasks. The brief agent reads the coverage opinion, not the database."""
    crew, defaults = _get_crew()
    inputs = {**defaults, **claim_to_inputs(claim, user_message)}
    result = crew.kickoff(inputs=inputs)
    labels = {
        "coverage_opinion": "Coverage opinion",
        "examiner_brief": "Examiner brief",
    }
    parts = []
    for task_output in result.tasks_output:
        heading = labels.get(task_output.name, task_output.name or "Task")
        parts.append(f"## {heading}\n\n{task_output.raw}")
    return "\n\n".join(parts)

Follow the small steps below in order. Use the terminal for the traced run, not the chat. The chat has no place to answer a yes-or-no question.

  • A crew can hold more than one agent. Each task names the agent who does it.
  • Sequential means the tasks run in the order written in crew.jsonc. The brief task waits until the coverage task has finished.
  • context is how the second task receives the first task's answer. The brief agent has no tools, so that answer is the only file it can read.
  • result.raw is only the last task. result.tasks_output is the full line of answers.
  • The tools did not move. Policy Record is still on the coverage officer agent. Earlier Claims is still on the coverage task alone.
  • "tracing": true sends that same run to your CrewAI account. The Traces tab is where you see the two tasks, the tool calls, and the opinion being passed into the brief.
