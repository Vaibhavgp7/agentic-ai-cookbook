1. What You Are Automating

A recruiter usually does three jobs in a row: turn a hiring manager’s short note into a job description, compare profiles with that description, and prepare interview questions. I have split that work into three skills so you can build them one at a time. Each skill does only its own job. The next skill uses what the previous one produced. You still review the draft. The skill does not hire anyone for you.

  1. hr-jd-generator — turns a rough hiring note into a standard job description and checks the draft.
  2. candidate-screener — scores profiles against that job description and writes recruiter notes.
  3. interview-kit-builder — turns the approved description and screening notes into interview questions.

2. How a Cursor Skill Is Built

A skill is a folder of instructions. When your prompt matches the description in that folder, Cursor follows the steps. You will put your skills under .cursor/skills/ in this project. Create the folders as you go. They are not waiting for you. 

.cursor/skills/your-skill-name/
├── SKILL.md              required — steps the agent must follow
├── some-rules.md         optional — read only when SKILL.md names the file
└── scripts/              optional — a checker the agent runs
    └── check.py

SKILL.md starts with a short header between two lines of three dashes. Two fields matter in Cursor:

  • name — lowercase letters, numbers, and hyphens only. It must match the folder name.
  • description — what the skill does and when to use it. Cursor reads this to decide whether the skill applies.

Write the steps in the body of SKILL.md. I am keeping the long template, the scoring rules, and the question rules in separate files so the main skill stays short. Name each file exactly, because the agent reads a file only when the steps tell it to.

After you save a skill, start a new Agent chat before you send the prompt. Cursor reads skill files when a chat starts. A chat that was already open will not see the files you just created.

# HR JD Generator

You are an HR Talent Acquisition Specialist at Northgate Solutions.

## Steps

1. Read the requisition. If role title, experience range, location, work mode, or must-have skills are missing, list them under "Clarifications needed" — do not guess.
2. Separate skills into Must-have and Good-to-have. Never promote a good-to-have to must-have.
3. Produce the JD using the layout in `jd-template.md`.
4. Apply every rule in `inclusive-language.md` before finalising.
5. Save the draft to `draft-jd.md` in the current working directory.
6. Run validation before returning the draft:
   ```bash
   python scripts/validate_jd.py draft-jd.md
   ```
7. If validation fails, fix the draft and re-run step 6. Only return the JD after validation passes.

## Rules

- Reference `.md` files by exact filename — no `@` prefix needed; Claude loads them on demand.
- Utility scripts live under `scripts/` — instruct execution with an explicit shell command (see step 6).
- Clear, inclusive, professional language. No exaggeration.
- Never include age, gender, marital status, nationality, college tier, or "culture fit" criteria.
- Do not invent compensation or approval details.
- Output is a DRAFT for human review.
Cursor uses name and description. I have left three extra lines in the header — context, allowed-tools, and argument-hint. Cursor ignores those lines, so your skill still runs in a normal Agent chat. Leave them in the file as I wrote them. If the checker cannot find scripts/validate_jd.py, tell the agent to run python .cursor/skills/hr-jd-generator/scripts/validate_jd.py draft-jd.md.

3.5 Write the checker script

I do not want you to trust the draft on the agent’s word alone. This script checks that the headings are present and that biased phrases did not slip in. The agent must fix the file and run the script again until it prints JD validation OK.

Your Task

Create .cursor/skills/hr-jd-generator/scripts/validate_jd.py, paste the following, and save it. 

#!/usr/bin/env python3
"""Lightweight JD draft checker for the hr-jd-generator skill."""

import re
import sys
from pathlib import Path

REQUIRED_SECTIONS = [
    "Job Title",
    "Company",
    "Role Overview",
    "Key Responsibilities",
    "Required Skills",
    "Preferred Skills",
    "Experience",
    "Location",
]

BIASED_TERMS = [
    "rockstar",
    "ninja",
    "guru",
    "young and energetic",
    "native english speaker",
    "iit-only",
    "tier-1 only",
    "culture fit",
]


def validate(text: str):
    errors = []

    for section in REQUIRED_SECTIONS:
        if section.lower() not in text.lower():
            errors.append(f"Missing section: {section}")

    lowered = text.lower()
    for term in BIASED_TERMS:
        if term in lowered:
            errors.append(f"Biased or non-inclusive term found: {term!r}")

    must_have = re.search(
        r"required skills|must-have", text, re.IGNORECASE
    )
    preferred = re.search(
        r"preferred skills|good-to-have", text, re.IGNORECASE
    )
    if must_have and preferred:
        start = must_have.start()
        end = preferred.start()
        if end > start:
            must_block = text[start:end].lower()
            if "preferred" in must_block or "good-to-have" in must_block:
                errors.append(
                    "Preferred skills appear inside the must-have section"
                )

    return errors


def main():
    if len(sys.argv) != 2:
        print("Usage: python scripts/validate_jd.py <draft-jd.md>", file=sys.stderr)
        return 2

    path = Path(sys.argv[1])
    if not path.is_file():
        print(f"File not found: {path}", file=sys.stderr)
        return 2

    errors = validate(path.read_text(encoding="utf-8"))
    if errors:
        print("JD validation FAILED:")
        for err in errors:
            print(f"  - {err}")
        return 1

    print("JD validation OK")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

# Candidate Screener

Screen each candidate against the provided JD.

## Steps

1. Read the JD. Identify must-have and good-to-have skills.
2. Apply the scoring method from `scoring-rubric.md`.
3. Apply every rule in `bias-guardrails.md` before writing notes.
4. For each candidate output: Fit Summary, Matched Skills, Gaps, Clarification Questions (2–3), Score /10, Recommendation (Shortlist / Hold / Reject), Reason.

## Rules

- Do NOT consider name, gender, age, college brand, employment gaps, or company brand.
- Do NOT invent information — mark missing details as "unclear — ask in recruiter call."
- Final decisions are human-owned.

# Candidate Screening Score Rubric

## Must-have gate

For each must-have: Met / Partial / Not met.

If 2+ must-haves are Not met, cap final score at 4.

## Scoring (0–10)

| Component | Max points |
|-----------|------------|
| Must-have coverage | 6 |
| Good-to-have coverage | 2 |
| Practical fit (location, notice, domain) | 2 |

## Score bands

| Score | Typical recommendation |
|-------|------------------------|
| 8–10 | Shortlist |
| 6–7.9 | Shortlist or Hold |
| 4–5.9 | Hold |
| Below 4 | Reject or Hold (if HM may flex) |

Always state: `Score: X/10 — [must-have: Y/6] + [good-to-have: Z/2] + [practical fit: W/2]`

# Bias Guardrails — Candidate Screening

## Do NOT consider

- Name, gender, age, graduation year as age proxy
- College or university tier
- Previous employer brand
- Employment gaps (unless role continuity is unclear from profile)
- Location of origin or accent assumptions

## DO consider (role-relevant only)

- Skills with project context
- Relevant years of experience
- Domain alignment (e.g. telecom OSS/BSS)
- Location/work-mode and notice period if stated in JD

## Language rules

- "React depth unclear" not "weak frontend background"
- Flag gaps as questions, not judgments
- Never reject on a single good-to-have gap

End every output with: "This is recruiter assistance only. Final decisions are owned by the recruiter and hiring manager."

# Interview Kit Builder

Prepare consistent, non-discriminatory interviews for shortlisted candidates.

## Inputs required

1. Approved job description
2. Screening notes (gaps and clarification themes)
3. Interview stage: recruiter screen / technical / hiring-manager

## Steps

1. Extract must-have and good-to-have competencies from the JD.
2. Map each competency using `competency-framework.md`.
3. For each screening gap, draft 1–2 targeted clarification questions.
4. Draft questions using rules in `question-bank-guide.md`.
5. Produce the kit in the output format below.

## Output format

### Interview Kit — [Role Title] — [Stage]

**Competencies to assess** — table: competency | why it matters | suggested depth

**Recommended questions (6–10)** — each with: question, what good looks like, red flags (skill gaps only)

**Follow-ups from screening notes**

**Questions to avoid for this role**

**Interviewer reminders**

Output is a DRAFT for the hiring manager to approve.

# Competency Framework — Technical hiring

| Competency | Assess via | Strong signal | Weak signal |
|------------|------------|---------------|-------------|
| Java / Spring Boot | Project walk-through | Describes modules owned, API design | Keyword only on resume |
| REST APIs | Design discussion | Verbs, errors, integration | Consumed APIs only |
| React | Scope question | Built components, state | "Basic exposure" with no example |
| SQL | Practical scenario | Queries, indexes at high level | ORM-only |
| Telecom domain | Domain story | OSS/BSS, billing context | Generic IT only |

Weight must-have competencies heavier in question count.

# Interview Question Guide

## Good patterns

- "Walk me through a recent project where you built REST APIs. What was your ownership?"
- "Tell me about a production issue you debugged in a Spring Boot service."
- "Describe a sprint where requirements changed mid-way. What did you do?"

## Bad patterns — do NOT generate

- Age or graduation year as proxy
- Personal life (marriage, children, health, religion)
- Trick puzzles unrelated to the role
- "Culture fit" — use collaboration and delivery behaviour instead

## Balance

- 60% role-specific technical or domain depth
- 30% behavioural / delivery
- 10% motivation and role understanding
